# Stage 15: Orchestration & System Design Plan

## 1. Task Decomposition & Idempotency

| Task Name | Inputs | Outputs | Idempotent | Rationale |
| :--- | :--- | :--- | :--- | :--- |
| `ingest` | `data/raw/data.csv` | `data/raw/prices_raw.json` | Yes | Overwrites the target JSON file with raw ingested data deterministically. |
| `clean` | `data/raw/prices_raw.json` | `data/processed/prices_clean.json` | Yes | Applies fixed cleaning transformations and explicitly overwrites the destination file. |
| `train_or_score` | `data/processed/prices_clean.json` | `models/model.json` | Yes | Trains/evaluates on static inputs and replaces the saved model weights/metrics. |
| `report` | `models/model.json` | `reports/report.txt` | Yes | Renders a summary evaluation report and overwrites any existing file at the path. |

---

## 2. Dependencies & Execution DAG

[ingest] ---> [clean] ---> [train_or_score] ---> [report]
* **Execution Order:** `ingest` → `clean` → `train_or_score` → `report`
* **Rationale:** Each step consumes the specific artifact generated by its predecessor. `clean` requires raw data, `train_or_score` requires cleaned features, and `report` requires saved model outcomes.

---

## 3. Logging & Checkpointing Strategy

* **Logging Directory:** `logs/pipeline.log` and standard output (`sys.stdout`).
* **Logged Details:** Start/end timestamps, input/output record counts, parameters, execution status, and exception tracebacks.
* **Checkpointing Strategy:** intermediate artifacts (`prices_raw.json`, `prices_clean.json`, `model.json`, `report.txt`) are written to disk upon successful completion of each step. If a step fails, re-running the pipeline can resume from the last valid checkpoint artifact.

---

## 4. Failure Points & Retry Policy

* **Primary Failure Point:** Network timeouts during ingestion or temporary disk write lock issues.
* **Retry Policy:** Exponential backoff with a maximum of 3 retries for transient execution failures.

---

## 5. Automation Strategy (Right-Sizing)

* **Automated Now:** Pipeline task execution via standard CLI commands (`src/run_step.py`), reproducible function invocations, logging, and checkpointing.
* **Kept Manual:** Multi-cloud orchestration (e.g., Airflow/Prefect deployment) and manual hyperparameter tuning triggers.
* **Rationale:** For the current project scope, CLI-driven Python scripts provide sufficient reproducibility and automation without introducing unnecessary infrastructure overhead.
